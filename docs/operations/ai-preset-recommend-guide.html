AI 프리셋 추천 — 기능 가이드 + 설계 유형 기록

발행 2026-06-07 · PR #777(백엔드)·#778(UI) · 관련: ADR 0112(Claude CLI bridge) · V70(프리셋 테이블) · V71(Core Wrapper DB 영속)

한 줄 요약 — "AI 프리셋 추천" 버튼은 살아있는 시스템 상태(Core Wrapper·기존 프리셋·실제 보유 지표)를 메타 프롬프트로 조립해 Claude에게 보내고, magicJar 구조로 검증 가능한 발굴 프리셋 후보를 받아온다. AI는 추천만 하고 저장은 사용자가 고른 것만 된다.

1. 사용 방법

① 버튼전략 리서치 → AI 종목발굴 → "AI 프리셋 추천" (violet)
② 방향 입력 (선택)"수급 기반 단타" 등 — 비워두면 기존 프리셋과 차별화된 컨셉 자동 제안
③ 추천받기Claude CLI 호출 — 수 분 소요 (진행률 바)
④ 카드 검토label·설명·지시문(접기)·rationale(왜 우리 구조에 맞는지)
⑤ 추가마음에 드는 것만 "프리셋으로 추가" → 발굴 드롭다운 즉시 노출

2. 설계 유형 — 왜 이 기능이 "Live-Context Meta-Prompt" 인가

이 기능의 본체는 UI가 아니라 메타 프롬프트 빌더(StrategyResearchAiDiscoveryService.buildPresetRecommendPrompt())다. 정적 템플릿이 아니라 호출 시점의 시스템 상태를 런타임 조립한다:

섹션데이터 출처 (권위)살아있는 이유
[core wrapper]corePromptText() — DB 권위 (V71, 사용자 편집본)사용자가 Core Wrapper를 개선하면 추천 기준도 즉시 따라감
[이미 등록된 프리셋]프리셋 테이블 전체 (V70 + 사용자 생성분)중복 컨셉 금지 — 프리셋이 쌓일수록 빈 전략 영역을 채우는 추천으로 이동
[magicJar 시스템 능력]IndicatorCatalog 직접 read (도메인 권위) — 카테고리별 지표 + 13 interval + 발굴→스크리너→백테스트 흐름지표를 추가/삭제하면 프롬프트가 자동 정합 — "보유하지 않은 데이터에 의존하는 프리셋 금지" 제약이 항상 실제와 일치
[사용자 힌트]요청 body hint (옵션)사용자 의도 최우선, 단 검증 가능성 제약 유지
[출력 계약]JSON only — label≤20자·description '~를 찾습니다' 톤·promptText 2~4문장 명령형·rationale 1문장기존 builtin 3종과 동일한 스타일로 수렴

선순환 사용 → Core Wrapper/프리셋/지표 개선 → 추천 품질 상승. 개선 레버는 코드가 아니라 ① Core Wrapper 텍스트 ② 메타 프롬프트의 [작업]·[출력 계약] 섹션 ③ IndicatorCatalog 확장 3곳이다.

3. 안전 원칙 (불변 — 향후 개선 시에도 유지)

  • AI 결정권 0 — 추천은 저장되지 않는다. 사용자가 "프리셋으로 추가"를 누른 것만 프리셋이 된다 (ADR 0112 정합: 주문·전략 저장·watchlist 자동 등록 0).
  • 프리셋 ≠ 매수 추천 — Screener+Backtest 검증을 거쳐야 하는 '가설 후보' 템플릿. 메타 프롬프트가 이 제약을 명시적으로 강제.
  • mock 합성 0 — AI 실패/타임아웃은 에러 그대로 표출, 재시도 가능.
  • 검증 가능성 게이트 — 보유 지표·interval로 검증 불가능한 프리셋(예: 외국인 수급 실시간 데이터 의존)은 추천 금지 지시.

5. 향후 개선 백로그 (아이디어 기록)

  • 품질 추천 프리셋의 사후 성과 피드백 루프 — 추가된 프리셋이 만든 후보의 스크리너 매칭률/백테스트 성과를 메타 프롬프트에 주입 ("성과 좋았던 프리셋 유형: …")
  • 품질 시장 컨텍스트 주입 — market_index_snapshot 추세 요약을 [작업] 섹션에 추가 (현재 장세에 맞는 프리셋)
  • UX 추천 결과에서 promptText 인라인 편집 후 추가 (현재는 추가 후 프리셋 설정에서 수정)
  • UX 추천 이력 보관 (현재 팝업 닫으면 소실 — discovery state 패턴 재사용 후보)
  • 동일 유형 재사용 이 Live-Context Meta-Prompt 패턴은 전략 DSL 추천·리스크 플랜 추천에도 동일 구조로 이식 가능 (카탈로그 read + 기존 자산 중복 회피 + 사용자 선택 저장)
