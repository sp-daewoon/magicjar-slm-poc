3. 실시간 이벤트 흐름 — 시세가 주문이 되기까지

Kafka 토픽으로 연결된 파이프라인. 각 단계는 독립 리스너가 소비.

KIS WS 틱 → Redis 진행봉 + market.tick → 1분봉 마감(TickToMinute) → candle.{1m~12h}.closed → 전략 평가(BoundaryClosing→SignalGenerator) → signal.generated
→ 리스크 게이트(SignalGenerated → RiskGateway) → 통과 시 order.intent → 주문 실행(OrderRouter → KIS 주문) → order.requested/filled/rejected
→ 체결 시 자동 익절 선주문(AutoExit) · 손절 감시(StopLossTickWatcher, 틱 기반 안전망 ●) → 화면으로 STOMP fanout
자본에 닿는 핵심 경로 — 주문 실행(OrderRouter)·리스크 게이트·자동 익절/손절·정합 워커들·outbox+KillSwitch. 3중 게이트(거래모드·KillSwitch·장시간) + 멱등키 + KIS 동기로 보호. 나머지(시세·캔들·뉴스·구독)는 정보 수집·표시 전용.
