★ 2026-06-09 전종목 일봉 마이그레이션 복구 기준점
KIS 채널 결함(UN/NX 일봉이 일부 종목 2026-02-11 동결) 근본 fix(J 단일, PR #844·#846) 후, 전체 일봉패밀리(1d·1wk·1mo·1y)를 wipe→J 채널로 재적재(보통주 2,517종목·10년). 그 직후 2026-06-09.dump(171MB)가 재구축된 전종목 일봉의 복구 baseline이다. 향후 일봉 손상 시 이 dump 복원 = 수 시간 재적재 없이 즉시 회복. 1m·5m 실시간 누적분(209만/43만 행)은 KIS REST 복구 불가이므로 이 dump가 사실상 유일 복원원(ADR 0105 1년 한도와 함께). 외부 매체 복사 권장.

2. 어떻게 남는가 — 생성 메커니즘

단계동작
1cron이 03:00 KST에 scripts/backup/pg-dump-daily.sh 실행
2magicjar-postgres 컨테이너 running 검증 (없으면 exit 1 + 로그)
3docker exec pg_dump -Fc(custom format — 압축 + 선택 복원 가능) → postgres/daily/YYYY-MM-DD.dump
47일 초과 파일 자동 삭제 (retention rotation) + 현재 목록 로그
503:30 redis-snapshot.sh — Redis BGSAVE 후 RDB 복사, 3일 회전

수동 1회 실행: bash scripts/backup/pg-dump-daily.sh — 재배포·릴리즈 cut 직전 의무 권장.

3. ⚠️ 반드시 알아야 할 경고 2건

🔑 .env + pg dump = 한 세트 (분리 보관 시 복구 불가) KIS app key/secret은 DB에 AES-256-GCM 암호화로 저장되는데, 그 암호화 마스터키(MAGICJAR_SECRET_MASTER_KEY)가 .env에만 있다. dump만 있고 .env가 없으면 KIS 자격증명은 복호화 불가. .env는 git 제외 파일이므로 백업 1순위다. (Anthropic/DART 키·DB 비밀번호도 .env에만 존재)
🕯️ "캔들은 다시 받으면 된다"는 절반만 맞다 1m봉은 KIS 서버가 최근 1년치만 보관한다(FHKST03010230). 지금 DB의 2025-12월~ 1m 데이터는 시간이 지나면 KIS에서 사라지고, 그때부터는 pg dump가 유일한 보존 수단이다. dump 7일 회전이므로 장기 보관본은 외부 매체에 주기적으로 복사할 것.

4. 외부 매체 복사 (PC 포맷 대비 — 의무)

_workspace/backups/는 .gitignore라 repo push로는 보존되지 않는다. 아래 최소 세트를 클라우드/USB에 복사:

대상경로비고
① .env/Users/ak-song/magic_ch1/.env시크릿 — 암호화된 매체 권장
② 최신 dump_workspace/backups/postgres/daily/<최신>.dump매주 1회 이상 갱신 복사
③ (선택) redis rdb_workspace/backups/redis/snapshots/휘발 캐시 — 없어도 자동 재구성
④ (선택) 기타 시크릿application-local.* · *.p12 · *.pem존재 시
 
# 예: 클라우드 동기화 폴더로 1줄 복사 (수동 또는 주간 cron)
rsync -a --delete _workspace/backups/ ~/Library/CloudStorage/<클라우드>/magicjar-backups/
cp .env ~/Library/CloudStorage/<클라우드>/magicjar-backups/env-$(date +%Y%m%d)

5. 복원 — pg-restore.sh (실증 완료)

# 1) dry-run — 복원 0건, dump 내용 미리보기
bash scripts/backup/pg-restore.sh --dry-run

# 2) 연습/검증 — 임시 DB에 복원 (운영 무손상)
bash scripts/backup/pg-restore.sh --target-db magicjar_restore_test --drop-after

# 3) 운영 DB 전체 복구 (DR — 앱 컨테이너 정지 선행)
bash scripts/backup/pg-restore.sh --target-db magicjar --confirm-prod

실증 evidence 2026-06-06 dump(56MB)를 임시 DB에 복원 — 테이블 56=56 · flyway V70=V70 · candle 2,545,735=2,545,735 · instrument 3,600=3,600 · 자격증명 2=2 row-level 일치 확인 후 임시 DB DROP (운영 0 touch).

새 PC 전체 복원(설치→clone→.env→인프라→restore→배포→검증)은 new-pc-migration-runbook.md C-1~C-7 참조.

6. cron 등록 (자동화 가동 — 사용자 1회 실행)

crontab -e   # 아래 2줄 추가
