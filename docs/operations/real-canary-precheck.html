1. 전략 만들기 — 빌더에서 이렇게 설정하세요

권장 전략 프로필 (canary 1회차)

항목권장값이렇게 하면
종목대형주 1개 (예: 005930)유동성 충분 → 시장가 슬리피지 최소
인터벌5m 이상 권장1m보다 시그널 빈도 낮음 → 일일 cap 여유
매수 조건이미 MOCK에서 검증한 조건식 그대로"전략이 좋은가"가 아니라 "배관이 안전한가"를 보는 날 — 조건은 바꾸지 않기
Sizing fraction최소 (0.01 수준)예산 기반 수량이 작아짐 — 어차피 hard cap이 1주로 막지만 이중 안전
분할 매수미사용 (OFF)canary 1회차는 단순 경로. PRICE_DROP 다회차는 미패치(F-1-OBS) — 분할 canary는 패치 후 2회차에서
손절(fixedStopLoss)-1.0% 내외아래 §2-B 표 참고 — 1주 기준 손실 수백 원 단위
익절(takeProfitPct)+1.5% 내외도달 시 전량 매도 시그널

저장 → 백테스트 1회 통과 → ACTIVE 전환까지가 "전략 준비 완료"입니다. canary 당일엔 이 전략 1개만 ACTIVE여야 합니다(나머지 전부 일시정지).

왜 이렇게 보수적인가

  • canary의 목적은 수익이 아니라 배관 검증 — 시그널→주문→체결→알림이 실돈에서 정확히 1:1 추적되는지
  • 전략 수익성은 MOCK·백테스트가 이미 검증 — 같은 조건을 그대로 가져가야 비교가 됨
  • 실패해도 잃는 돈이 "용돈 수준"이 되도록 모든 한도를 겹겹이 — 아래 §2가 그 계산

준비 순서 요약

  • ① 전략 생성·백테스트 (지금부터 가능)
  • ② MOCK으로 며칠 관찰 — 시그널·주문이 기대대로 (지금 단계)
  • ③ 체크리스트 G/K/P/S/O 항목 준비 (아래 §3)
  • ④ 실행일 결정 → 당일 아침 staging 30분 → REAL ON

2. 설정값 → 기대 결과 매트릭스

2-A. canary hard cap ENV 3종 (.env에 입력 — ADR 0109)

ENV권장값이 값이면 어떤 결과가 되나초과 시 시스템 반응
MAGICJAR_CANARY_MAX_ORDER_QTY1어떤 주문도 1주를 넘을 수 없음 — 전략·예산 계산이 실수해도 1주주문이 KIS로 나가기 전 REJECTED(CANARY_QTY_CAP) + Slack 알림
MAGICJAR_CANARY_MAX_ORDER_NOTIONAL_KRW1000001건당 최대 10만원 — 10만원 넘는 주가 종목은 1주도 거부됨(종목 선정 시 주가 확인)REJECTED(CANARY_NOTIONAL_CAP)
MAGICJAR_CANARY_MAX_ORDERS_PER_DAY5하루 REAL 주문 5건에서 멈춤 — 매수+매도 합산이므로 실질 2~3 사이클6번째부터 REJECTED(CANARY_DAILY_CAP) — 다음날 자동 리셋

3개 모두 0 또는 미설정이면 cap 비활성(일반 운용) — canary 당일엔 반드시 3개 다 설정돼 있어야 하며 체크리스트에서 제가 printenv로 실측 확인합니다. MOCK 모드에서는 cap이 작동하지 않으므로 지금 미리 넣어둬도 현 운용에 영향 없습니다.

2-B. 최악 손실 시나리오 계산 (권장값 기준)

시나리오계산기대 결과
정상 손절70,000원 종목 1주 × -1%-700원/회
하루 전부 손절 (cap 5건 = 매수3·매도2 가정)3회 × -700원 + 수수료약 -3,000원 수준
손실한도 도달RiskConfig dailyLossLimit=50,000원-5만원 도달 시 그날 BUY 전면 차단 (이론상 상한)
최악(갭 하락 + 손절 미체결)1주 notional 10만원이 휴지가 되는 극단 가정-10만원이 절대 상한 — 동시 보유 1종목 한도 때문

즉 겹겹의 한도로 "이론상 최악 -10만원, 현실적 기대 -수천 원 내" 박스가 만들어집니다.

5. 사전 패치 권고 (canary 전 오케스트라가 처리)

권고 F-1-OBS — PRICE_DROP 다회차 주입

분할매수 PRICE_DROP 트리거의 2회차+ 재진입이 현재 비활성(미패치). canary 1회차(분할 OFF)에는 영향 없지만, 분할 canary(2회차)를 하려면 선행 패치 필수.

선택 재배포 WS 공백 graceful 정리

재배포 직후 KIS 잔존 세션으로 다음 정각까지 WS 공백 발생 — canary 당일 아침 재배포 금지(전일 저녁 배포 완료)로 절차상 회피 가능. 패치는 선택.
