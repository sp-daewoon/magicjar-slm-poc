실시간 구독 플로우

Browser는 KIS나 Kafka에 직접 붙지 않습니다. Browser는 api의 STOMP 방에 들어가고, KIS WebSocket은 consumer app이 직접 연결합니다.

1. Browser가 api의 /ws에 연결하고 STOMP 방을 구독
2. Browser가 REST로 실시간 수요 등록 요청
3. api가 command topic에 ENTER produce
4. consumer app은 command를 이미 consume 중
5. consumer app이 KIS WS에 종목 subscribe
6. KIS 실시간 tick/호가가 consumer app으로 내려옴
7. consumer app이 market topic에 시세 produce
8. api가 market topic을 consume
9. api STOMP broker가 Browser 방으로 push

Browser가 직접 하는 일

/ws WebSocket에 연결하고 /topic/market.tick.030000 방을 구독합니다. Kafka나 KIS에는 직접 붙지 않습니다.

Command topic의 의미

symbol.detail.command.v1은 시세 데이터가 아니라 "030000 상세 화면 ENTER/EXIT" 같은 작업 지시를 담습니다.

consumer app의 역할

consumer app은 Kafka 자체가 아닙니다. KIS WebSocket client이면서, command topic consumer이고 market topic producer입니다.
