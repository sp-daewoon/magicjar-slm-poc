⚠ 가장 먼저: 작업 디렉토리

모든 명령은 기준 위치가 둘로 나뉜다. git/docker 명령은 레포 루트에서, 파이썬/스트림릿 명령은 slm-lab/ 안에서 실행한다. 헷갈리면 항상 절대경로로 루트부터 잡아라:

cd /Users/ak-song/magicjar-slm-poc      # ← 항상 여기서 시작

예를 들어 학습서를 열 때 slm-lab/ 안에서 open docs/학습/index.html 을 치면 "파일이 없습니다"가 난다 (그 경로엔 slm-lab/docs/... 가 없으니까). 루트에서 열거나 절대경로를 쓰면 된다:

open /Users/ak-song/magicjar-slm-poc/docs/학습/index.html

0. 준비물 (한 번만)

도구확인 명령없으면

개념 · 무엇이 어디서 도나

Ollama는 모델을 돌리는 엔진(생성 Gemma3:4b + 임베딩은 BGE-M3는 파이썬 쪽에서 로드). Qdrant·Phoenix는 도커 컨테이너. RAG 코드/Streamlit은 slm-lab/의 파이썬. 이 셋이 따로 떠 있어야 전체가 돈다.

1. 인프라 띄우기 (레포 루트에서)

cd /Users/ak-song/magicjar-slm-poc
docker compose -f docker/docker-compose.slm-rag.yml up -d   # Qdrant(16333) + Phoenix(16006)
ollama serve &                                             # 이미 떠 있으면 생략
ollama pull gemma3:4b                                       # 한 번만 (~3.3GB)

떴는지 확인:

curl -s localhost:16333/healthz   && echo " ← Qdrant OK"
curl -s -o /dev/null -w "%{http_code}" localhost:16006 ; echo " ← Phoenix (200이면 OK)"
curl -s localhost:11434/api/tags  > /dev/null && echo "Ollama OK"

2. 파이썬 의존성 설치 (slm-lab 안에서)

cd /Users/ak-song/magicjar-slm-poc/slm-lab
uv sync                                                     # 가상환경 + 라이브러리 설치

3. 인덱싱 — 레포를 검색 가능한 형태로 (한 번, 또는 코드 바뀌면 다시)

cd /Users/ak-song/magicjar-slm-poc/slm-lab
uv run python -m rag.indexing
# 기대 출력: indexed files=71 chunks=1095  (처음엔 BGE-M3 다운로드로 몇 분 소요)
가설/메모

처음 실행은 BGE-M3(~2GB) 다운로드 때문에 느리다. 두 번째부터는 캐시되어 빠르다. 파일 수/청크 수가 0이면 rag/config.py의 INCLUDE_DIRS 경로가 실제 레포 구조와 맞는지 확인하라.

4. 체험 & 관측

4-1. Streamlit 챗 (눈으로 RAG 보기)

cd /Users/ak-song/magicjar-slm-poc/slm-lab
uv run streamlit run rag/app.py --server.port 18501
# 브라우저: http://localhost:18501  (질문 입력 → 답변 + 검색청크/점수 + 최종 프롬프트 펼침)

4-2. Phoenix 트레이스 (현업식 해부)

브라우저에서 http://localhost:16006 — 질문을 한 뒤 트레이스를 열면 retrieve→LLM 스팬, 청크·점수·프롬프트·지연이 보인다. (자세한 화면은 3장.)

4-3. Qdrant 대시보드 (저장된 벡터)

http://localhost:16333/dashboard — 컬렉션 magicjar_slm, 1,095 포인트, 차원 1024, Cosine.

4-4. 학습서(이 책) 열기

open /Users/ak-song/magicjar-slm-poc/docs/학습/index.html

5. 평가 — Opus만큼인가 (선택, claude CLI 필요)

cd /Users/ak-song/magicjar-slm-poc/slm-lab
uv run python -c "from eval.run_eval import run_eval; run_eval(limit=2)"   # 소규모 스모크(2문항)
uv run python -m eval.run_eval                                            # 전체 30문항 (~30분)
# 결과: slm-lab/eval/results.csv , results.md
⚠ 알려진 한계 (정상 동작)

현재 의존성에서 Ragas 3지표는 NaN으로 나온다(ragas 라이브러리 import 버그를 try/except로 우아하게 강등). 이건 버그가 아니라 의도된 방어이며, 지금의 실측 신호는 Opus 심판 점수(winner·gemma_score)다. 자세한 이유는 4장.

6. 정리(끄기)
