핵심 결론 — ① 자동매매는 진입·청산 전부 시장가 고정이며 가격 보호 정책 0. ② KIS 국내주식 OpenAPI에 서버 예약형 스탑로스는 존재하지 않아 클라이언트 감시가 유일한 경로 = 우리 시스템이 곧 스탑로스. ③ 그 감시 구조는 backend 독립(화면 무관)으로 견고하나, "항상"의 보장에 구멍 4개 — 특히 readiness fail-closed가 손절까지 막는 것과 DISABLED 전략의 보유 포지션 방치는 Critical.

§4. 포지션 "긴장 상태" 검토 — 8개 축 매트릭스 (코드 전수)

평가 체인 (실제 구조)

KIS WS tick → boundary 집계 → Kafka market.candle.1m.closed.v1
  → BoundaryClosingKafkaListener (consumer)
  → RealtimeSignalGenerator.onBoundaryClosed()
     ├─ ① market-hours gate (09:00~15:30만)      RealtimeSignalGenerator.kt:136-143

§5. 위험 우선순위 + 복구 방향

순위위험시나리오복구 방향
P1readiness가 손절까지 skip (§4-5)보유 종목 캔들 reconciliation 중 손절가 이탈 → 평가 자체가 skip → 손실 확대게이트를 진입/청산 분화 — 보유 포지션의 SELL 평가는 readiness 우회(또는 STALE 한정 진행). fail-closed는 "신규 자본 투입 차단"에만
P2DISABLED 전략 포지션 방치 (§4-7)전략 A로 매수 → A가 auto-disable → 손절가 도달 → 전략 조회에 안 잡혀 청산 신호 미발행전략 상태와 무관하게 position 보유 종목은 무조건 청산 평가 대상(BUY만 상태 게이트) 또는 DISABLED를 SELL-only로 포함
P3HOLDING owner 부재 (§4-3)watchlist에서 뺀 보유 종목이 slot 경합에서 evict → tick 끊김 → 1m 캔들 미생성 → 평가 불가owner enum에 HOLDING(최우선·evict 금지) 추가 + 체결 시 자동 등록/전량 청산 시 해제
P4NXT 시간대 손절 차단 (§4-6)15:30 이후 NXT에서 급락 → gate가 SELL 평가도 차단 → 다음날 갭으로 손실gate를 BUY 한정으로 분리 (market-hours-gate-for-sell=false) — 단 NXT 유동성 고려해 사용자 결정 필요
P5폴링 fallback 1d 한정 (§4-4)WS 장애 + evict 동시 발생 시 1m 재료 공백보유 종목 한정 1m 폴링 경로 추가 (HOLDING owner와 함께 설계)
