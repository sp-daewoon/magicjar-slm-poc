한 줄 요약

AI가 HLB 같은 종목을 찾아왔을 때, 이제 “종목 마스터에는 매칭됐지만 현재 선택한 5분봉 기간에는 캔들이 0개”라는 상태를 카드에서 바로 보여줍니다. 그리고 0개 후보는 리서치 대상으로 선택하지 못하게 막았습니다.

동시에 전략 평가·실시간 신호·스크리너의 캔들 조회는 전체 fetch 후 자르기에서 DB 최신 N개 조회로 바뀌었습니다.

1. AI 종목발굴 후보 카드

기존

  • AI 후보가 종목 마스터에 매칭되면 바로 선택 가능했습니다.
  • 선택 후 리서치를 눌러야 캔들 0개 경고를 봤습니다.
  • HLB처럼 “찾긴 찾았는데 캔들이 없음” 상태가 카드에서는 드러나지 않았습니다.

변경 후

  • AI 발굴 요청에 현재 리서치 조건 interval, from, to가 같이 전송됩니다.
  • API가 후보별 candleCount, hasResearchCandles를 계산해 반환합니다.
  • 카드에 캔들 N 또는 캔들 없음 배지를 표시합니다.
  • candleCount = 0이면 선택 버튼이 비활성화됩니다.

2. 캔들 조회 방식

경로 기존 변경 후 의미
전략 단건 평가 findByCodeAndInterval(...).takeLast(N) findLatestByCodeAndInterval(..., N) 전체 시계열 대신 DB에서 최신 N개만 조회합니다.
실시간 신호 평가 전체 조회 후 boundaryTs 이하 필터링 ts < boundaryTs 조건으로 최신 N개 조회 boundary candle 중복을 피하고 읽는 row 수를 줄입니다.
스크리너 종목마다 전체 캔들 조회 max(lookback, minCandles)만 최신 조회 유니버스가 커질 때 DB I/O가 줄어듭니다.
합산봉 재생성 1m 전체 조회 그대로 유지 3m·5m 등 합산봉 재생성은 전체 1m이 필요해서 의도적으로 유지했습니다.

3. DB 인덱스

기존

  • idx_candle_code_interval_ts가 있었습니다.
  • idx_candle_code_interval_ts_v8도 같은 형태로 있었습니다.
  • uq_candle_code_interval_ts는 중복 방지와 upsert에 필요했습니다.

변경 후

  • idx_candle_code_interval_ts만 V69로 제거했습니다.
  • idx_candle_code_interval_ts_v8는 최신 조회용으로 남겼습니다.
  • uq_candle_code_interval_ts는 upsert와 유니크 보장을 위해 남겼습니다.

적용 확인: Flyway V69 성공. 현재 남은 candle 관련 인덱스는 idx_candle_code_interval_ts_v8, uq_candle_code_interval_ts입니다.

정책 문서 추가

별도 문서 2026-06-06-candle-operating-policy-options.md를 추가했습니다. 이 문서는 “전체 종목 일봉 + 관리 유니버스 intraday”를 추천안으로 설명하지만, 실제 retention cleanup이나 전체 종목 일봉 수집 정책은 아직 구현하지 않았습니다.

바뀌지 않은 것

  • 기존 candle row는 삭제하지 않았습니다.
  • 모든 종목 1분봉 수집 정책을 켜지 않았습니다.
  • 캔들 retention cleanup 스케줄러는 아직 만들지 않았습니다.
  • AI 후보에서 바로 캔들 수집하는 버튼은 아직 만들지 않았습니다.
  • 자동매매 주문·포지션·실거래 로직은 바꾸지 않았습니다.
  • 합산봉 생성 정책 자체는 바꾸지 않았습니다. 1m 원천 + precomputed aggregate 방향은 유지입니다.

되돌릴 수 있는 범위

항목 되돌리기 난이도 설명
AI 카드의 캔들 배지·선택 차단 낮음 프론트와 DTO/API 보강이라 되돌리기 쉽습니다.
최신 N개 조회 경로 중간 성능 개선 목적이라 유지 권장입니다. 동작 의미는 기존 lookback과 같습니다.
중복 인덱스 제거 V69 중간 필요하면 인덱스를 다시 만들 수 있지만, 현재는 중복이라 복구 필요성은 낮습니다.

아직 결정해야 하는 것

  • AI가 찾은 후보에 캔들이 없을 때, 사용자가 버튼 하나로 수집 큐를 넣을지.
  • 전체 종목은 일봉만 들고 갈지, 거래대금 상위 일부는 분봉까지 자동 편입할지.
  • 1m, 3m, 5m, 15m 이상 interval별 retention 기간을 어떻게 확정할지.
  • 캔들 테이블이 몇 GB 이상이면 파티셔닝 또는 별도 저장소를 검토할지.
